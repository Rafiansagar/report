Rehouz Real Estate — Project Status

Date: 25 October 2026 Product: one free WordPress real-estate plugin Builder: Elementor only

Where the project stands

The plugin works end to end today. A site owner can install it, add listings, agents and agencies from our own admin, and a visitor can browse, search, filter, see listings on a map, save favourites, compare, send an inquiry, register, sign in and submit their own listing. Search, maps, leads, user accounts and the admin dashboard are all built.

The work happening right now is the Elementor front end: giving every widget a full set of design controls so a site can be built visually without touching code. One widget of eight is design-complete. After that come the remaining widgets, then testing and the WordPress.org submission.

1. Done — Backend / data

  • Plugin foundation: activation, database tables, upgrade routine, settings storage
  • Listings, agents, agencies and projects (off-plan developments) as content types
  • Twelve categorisation lists (type, status, city, area, features, amenities, labels…)
  • Full listing field set — price, size, rooms, year, floor plans, documents, energy, rental terms, virtual tour
  • Custom field builder — a site owner can add their own fields
  • Search index table kept in sync automatically, with a rebuild tool
  • Search engine: filters, sorting, paging, result caching
  • Map search by distance ("near me", radius)
  • Lead capture: inquiry forms, storage, email notifications, spam protection (honeypot, rate limit, optional reCaptcha)
  • Favourites and compare, for logged-in users and guests
  • Reviews storage and moderation
  • Saved searches with hourly email alerts
  • Listing expiry — expired listings go back to draft automatically
  • Google rich results (listing schema) for SEO
  • Maps: OpenStreetMap and Google Maps, with marker clustering
  • Image sizes registered so listing photos load fast
  • CSV import and export for all four record types
  • Location importer: browse country / state / city / area, tick what is needed and import it as categories, so a new site does not mean typing locations by hand

Risks worth flagging

  1. Design work is the slow part, and there are two fronts of it. The Elementor widget controls (seven widgets remain, roughly a day each) and the admin redesign are separate pieces of work that cannot share effort.
  2. Performance is designed for, not proven. The 50,000-listing target needs a real dataset before we can claim it.
  3. Email, lead flows and reCaptcha have not been run against live services — only local. Needs a staging pass.
  4. WordPress.org review is a queue, not a date. A rejection costs weeks, so the checklist pass in section 8 should not be rushed.
  5. MLS import is open-ended. Every MLS feed is shaped differently; scope needs pinning to specific feeds before it can be estimated.
  6. The templates were built plain on purpose. Correctness first, design second — so matching them to the design is a known, sizeable piece of work, not a surprise. It is the largest single item left on the front end after the widgets.
  7. The location dataset is served from our own server. Two countries are published today. Until the full set is there, and ideally a copy ships inside the plugin, a site without internet access cannot import locations.
